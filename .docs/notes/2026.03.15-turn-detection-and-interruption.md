# Turn Detection & Interruption: Two Independent Systems

Two separate systems handle "when to act on user speech," and they operate in different states.

## 1. Endpointing (Turn Detection)

**When:** User is speaking (state = LISTENING/HEARING)
**Question:** "Has the user finished their thought?"
**File:** `server/voice/endpointing.ts`

Triggered on VAD `SPEECH_END`. Three tiers, in priority order:

1. **Smart Turn** (ML model) — if enabled, runs the ONNX model on the last 8s of audio. Returns a probability (0-1) that the turn is complete. Uses Whisper mel features + a fine-tuned classifier.
2. **Word-count fast path** — if transcript has enough words (>= `minWordCountForFastPath`), assume complete.
3. **Haiku semantic check** — for short/ambiguous utterances, asks Claude Haiku "is this a complete turn?"

Logs: `Smart Turn: probability=X, complete=Y, Zms`

## 2. Interruption Detection

**When:** AI is speaking (state = SPEAKING/PROCESSING)
**Question:** "Is the user trying to interrupt?"
**File:** `server/voice/voice-session.ts` (functions: `handleInterruptionDetection`, `handleSoftInterruption`, `verifyInterruption`)

Two-phase approach to avoid false interruptions from backchannels ("mm-hmm") or background noise:

1. **Soft interrupt** — VAD detects speech during AI output. After `thresholdMs` of sustained speech, TTS is paused.
2. **Verify** — The captured audio is transcribed. If word count >= `minWords`, it's a real interruption → cancel TTS + Claude, transition to LISTENING. Otherwise → resume TTS.

Logs:
- `Soft interruption -- pausing TTS, verifying...`
- `Interruption transcript: "..." (N words)`
- `User interruption confirmed` OR `False interruption -- resuming TTS`

## Key Difference

- **Endpointing** decides when to *start* processing the user's input
- **Interruption** decides when to *stop* the AI's output

They never run at the same time — endpointing runs in LISTENING state, interruption runs in SPEAKING state.
