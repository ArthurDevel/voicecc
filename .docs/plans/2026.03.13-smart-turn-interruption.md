# Plan: Smart Turn End-of-Turn Detection + Interruption Recovery

## High-Level Goal

Improve two voice UX problems:

1. **Agent starts too fast**: Replace immediate turn-completion on VAD silence with Smart Turn v3.2 model inference to distinguish "user is thinking" from "user is done".
2. **Interruption too slow**: Lower the interruption threshold from 1500ms to 500ms and add false-interruption recovery so the agent can resume if the interruption was a false alarm (backchannel, noise).

### smart-turn.ts (NEW)

Wraps the Smart Turn v3.2 ONNX model. Handles mel spectrogram feature extraction and inference.

#### Types

```
SmartTurnPredictor {
  predict(audioBuffer: Float32Array): Promise<SmartTurnResult>
  destroy(): void
}

SmartTurnResult {
  isComplete: boolean       // true if probability > threshold
  probability: number       // raw sigmoid output 0-1
  inferenceMs: number       // inference duration for logging
}
```

#### Methods

| Method | Arguments | Returns | Description |
|--------|-----------|---------|-------------|
| `createSmartTurnPredictor` | `config: SmartTurnConfig` | `Promise<SmartTurnPredictor>` | Loads ONNX model + Whisper feature extractor, returns predictor instance |
| `predict` | `audioBuffer: Float32Array` | `Promise<SmartTurnResult>` | Truncates/pads audio to 8s, extracts mel features, runs ONNX inference |
| `destroy` | none | `void` | Releases ONNX session resources |

### endpointing.ts (MODIFIED)

Remains a **stateless** decision function (no timers). Timers live in voice-session.ts.

#### Changes

- `onVadEvent` receives an additional `audioBuffer: Float32Array` parameter containing the accumulated audio from the speech segment
- On `SPEECH_END`: if Smart Turn is enabled, run `smartTurnPredictor.predict(audioBuffer)` instead of word-count fast path
- If Smart Turn says incomplete (`isComplete: false`), return `{ isComplete: false }` -- voice-session handles the timeout
- If Smart Turn says complete, return `{ isComplete: true, method: "smart_turn" }`
- Word-count fast path and Haiku fallback remain as options when Smart Turn is disabled
- `createEndpointer` accepts optional `SmartTurnPredictor` instance

| Method | Arguments | Returns | Description |
|--------|-----------|---------|-------------|
| `createEndpointer` | `config: EndpointingConfig, smartTurn?: SmartTurnPredictor` | `Endpointer` | Creates endpointer, optionally with Smart Turn predictor |
| `onVadEvent` (updated) | `event: VadEvent, currentTranscript: string, audioBuffer?: Float32Array` | `Promise<EndpointDecision>` | Now accepts audio buffer for Smart Turn inference |

### voice-session.ts (MODIFIED)

#### Changes to end-of-turn flow

- **Parallel audio buffer**: accumulate raw audio in a `Float32Array[]` buffer alongside STT accumulation (reuse existing `accumulating` flag). Cap at 128,000 samples (8s at 16kHz) by dropping oldest chunks.
- **Cross-segment transcript accumulation**: add a `turnTranscript: string` buffer that appends each segment's transcript when Smart Turn says incomplete. Clear on `handleCompleteTurn`. Pass the accumulated `turnTranscript` to `handleCompleteTurn` instead of just the current segment's text.
- On `handleSpeechEnd`, pass accumulated audio buffer to `endpointer.onVadEvent(event, transcript, audioBuffer)`
- If endpointer returns `isComplete: false`, STT buffer is already cleared by `transcribe()`, keep audio buffer, stay in LISTENING
- **Incomplete-timeout**: on incomplete result, start a `smartTurnTimeoutTimer` (3000ms). If it fires without new speech, force-complete with the accumulated `turnTranscript`. If `SPEECH_START` fires, cancel the timer and continue accumulating.
- **Concurrent speech during inference**: if `SPEECH_START` fires while a Smart Turn prediction is in-flight, ignore the prediction result and continue accumulating. The user has resumed speaking, so the segment was clearly incomplete.

#### Changes to interruption flow

- Lower default threshold from 1500ms to 500ms (browser) / 800ms (Twilio)
- On interruption timer firing: **pause** TTS output via `ttsPlayer.pause()` (don't cancel yet)
- Start transcribing the interruption audio
- If 2+ words transcribed -> commit: cancel TTS + Claude, transition to LISTENING
- If no words / empty transcript within `falseInterruptionTimeoutMs` (2000ms) -> **resume** TTS output via `ttsPlayer.resume()` (false interruption recovery)
- During pause, Claude's token stream continues and `speakStream` buffers sentences but does not write to speaker. On resume, buffered sentences are written. On commit, the generator is aborted.
- New closure-scoped state: `interruptionPending: boolean`, `interruptionResumeTimer`

| Method | Arguments | Returns | Description |
|--------|-----------|---------|-------------|
| `handleInterruptionDetection` (updated) | `event: VadEvent` | `void` | Now pauses instead of immediately cancelling, starts word-count verification |
| `handleSoftInterruption` (new) | none | `void` | Pauses TTS, transcribes interruption audio, commits or resumes based on word count |

### tts-elevenlabs.ts (MODIFIED)

#### TTS pause/resume mechanism

Add a Promise-gate pattern for pause/resume. The `speakStream` loop `await`s a `pauseGate` promise between chunks:

- `pause()`: create a new unresolved `pauseGate` promise. The loop hits `await pauseGate` and suspends without breaking. The ElevenLabs HTTP stream continues, chunks are buffered in memory.
- `resume()`: resolve the current `pauseGate`. The loop wakes up and continues writing buffered chunks to the speaker.
- `interrupt()`: existing behavior -- sets `interruptFlag = true`, resolves `pauseGate` (if paused), loop breaks.

This is the core distinction:
- `interrupt()` = break out of the loop, cancel everything
- `pause()` = suspend the loop, keep buffering
- `resume()` = wake the loop, flush buffer

### tts-provider.ts (MODIFIED)

Thread a `pausePlayback` callback through the TTS factory (alongside existing `interruptPlayback` and `resumePlayback`).

### browser-server.ts / twilio-server.ts (MODIFIED)

Update config construction to use new types:
- `endpointing.smartTurn: { modelPath: "server/voice/assets/smart-turn-v3.2-cpu.onnx", threshold: 0.5, enabled: true }`
- `interruption: { thresholdMs: 500, minWords: 2, falseInterruptionTimeoutMs: 2000 }`

Note: Twilio uses `thresholdMs: 800` (higher due to no AEC). The structural change from `interruptionThresholdMs: number` to `interruption: InterruptionConfig` means config construction code must be updated, not just values.

## Important Technical Notes

### Audio buffer management for Smart Turn

Smart Turn needs the raw audio from the current speech segment (up to 8 seconds, right-aligned with zero-padding at the start). The STT processor already accumulates audio via `sttProcessor.accumulate(samples)`, but we can't extract it back (and `transcribe()` clears the buffer). We need a parallel `Float32Array[]` buffer in `voice-session.ts` that collects the same chunks. On `SPEECH_END`, concatenate and pass to Smart Turn. Cap at 128,000 samples (8s) by dropping oldest chunks.

### Cross-segment transcript accumulation

When Smart Turn returns "incomplete", the user continues speaking across multiple SPEECH_START/SPEECH_END cycles. Each segment is transcribed independently. A `turnTranscript` string in voice-session.ts accumulates these: `turnTranscript += " " + segment.text`. This accumulated transcript is passed to `handleCompleteTurn` when Smart Turn finally returns "complete" or the timeout fires.

### TTS pause gate (Promise pattern)

The `speakStream` loop in `tts-elevenlabs.ts` currently checks `interruptFlag` at multiple points to break out. For pause, add a `pauseGate` promise between the check points:

```
// Between chunks in the speakStream loop:
if (interruptFlag) break;
await pauseGate;  // resolves immediately when not paused, blocks when paused
```

On `pause()`: replace `pauseGate` with a new unresolved promise + store its resolver.
On `resume()`: call the stored resolver, set `pauseGate` to `Promise.resolve()`.
On `interrupt()`: also resolve `pauseGate` so the loop wakes up and hits the `interruptFlag` break.

### ONNX Runtime coexistence

Both `avr-vad` (Silero VAD) and Smart Turn use ONNX Runtime. The `avr-vad` package bundles its own ONNX runtime. Potential native symbol conflicts exist. **Phase 0 validation step**: before implementing anything, create a minimal test that loads both `avr-vad` and `onnxruntime-node` in the same Node.js process. Also validate Whisper mel feature extraction performance to de-risk Phase 1. If conflicts occur, run Smart Turn in a worker thread.

### Whisper feature extraction in Node.js

Smart Turn requires Whisper-format mel spectrogram features (80 mel bins, 800 frames for 8s audio). Options:
- `@huggingface/transformers` npm package includes `WhisperFeatureExtractor`
- Or port the feature extraction manually (STFT + mel filterbank + log + normalize)

The `@huggingface/transformers` package is large. If bundle size matters, a manual port of just the feature extraction (~100 lines) is preferable. Evaluate during Phase 0.

### Twilio pause limitations

Twilio's audio buffer is server-side. A `clear` event flushes it, but there is no `pause` equivalent. For Twilio, `pause()` at the TTS level means we stop calling `writeSpeaker()` -- but audio already sent to Twilio will play. This means false-interruption recovery on Twilio will have a brief audio gap. Acceptable for Phase 2; a more sophisticated Twilio-specific solution can follow later.

## Success Criteria

- Mid-sentence pauses (1-2 seconds) no longer trigger agent response
- Complete sentences still trigger agent response within ~100ms of Phase 0 baseline latency
- If Smart Turn returns "incomplete" but user is truly done, timeout fallback triggers within 3 seconds
- Multi-segment turns (user pauses mid-thought, continues) produce a correct combined transcript
- Interrupting the agent works within 500ms instead of 1500ms
- Backchannels ("yeah", "okay") during agent speech do not interrupt the response
- No regression in existing voice call quality for browser or Twilio
- Smart Turn inference (including mel extraction) adds less than 100ms to end-of-turn detection
