# Agent Marketplace

## Goal

Add a community marketplace where users can publish their voice agents and browse/download agents shared by others. Agents are stored as zip archives in an S3 bucket with JSON metadata. The dashboard gets a new "Marketplace" page for browsing/downloading/installing and a "Publish" button on agent detail. The lander gets a "Community Agents" section. A new API layer handles uploads, downloads, and listing.

## Types and Methods Per File

### server/services/marketplace.ts (NEW)

S3 client for the agent marketplace. Uses a SeaweedFS instance with S3-compatible API. Stores zips at `<id>.zip` and metadata at `<id>.json` in the `agents` bucket. Uses `@aws-sdk/client-s3` with `forcePathStyle: true` for SeaweedFS compatibility. Listing is done by scanning the bucket for `*.json` files (no central registry file). S3 client and list cache are module-level singletons (lazy-initialized on first call).

#### Types

```
MarketplaceAgentMeta {
  id: string                          // unique marketplace ID (format: "<author>-<agentId>")
  name: string                        // display name (defaults to local agent ID)
  description: string                 // short description
  author: string                      // publisher name (user-provided)
  version: string                     // semver string, e.g. "1.0.0"
  tags: string[]                      // searchable tags
  publishedAt: string                 // ISO 8601 timestamp
  size: number                        // zip file size in bytes
}

PublishAgentParams {
  agentId: string                     // local agent ID (used to call exportAgent)
  name: string                        // display name
  description: string                 // short description
  author: string                      // publisher name
  version: string                     // semver string
  tags: string[]                      // searchable tags
}
```

#### Methods

| Method | Arguments | Returns | Description |
|--------|-----------|---------|-------------|
| `listMarketplaceAgents` | none | `Promise<MarketplaceAgentMeta[]>` | Lists objects in the `agents` bucket filtered to `*.json` via `ListObjectsV2Command`, fetches each, returns parsed array. Uses module-level cache with 60s TTL. |
| `publishAgent` | `params: PublishAgentParams` | `Promise<MarketplaceAgentMeta>` | Calls `exportAgent(agentId)` to get zip, strips MEMORY.md from the zip buffer, uploads zip to `<id>.zip`, writes metadata to `<id>.json`. Overwrites if same ID exists (upsert). Invalidates list cache. |
| `downloadAgent` | `id: string` | `Promise<Buffer>` | Fetches `<id>.zip` from S3 and returns the buffer. Throws if agent not found. |
| `getMarketplaceAgent` | `id: string` | `Promise<MarketplaceAgentMeta>` | Fetches `<id>.json` from S3 and returns the metadata. Throws if not found. |
| `deleteMarketplaceAgent` | `id: string` | `Promise<void>` | Deletes both `<id>.zip` and `<id>.json` from S3. Invalidates list cache. |
| `getS3Client` | none | `S3Client` | Returns the module-level S3Client singleton, creating it on first call. Configured with `forcePathStyle: true` for SeaweedFS. Uses env vars `S3_ENDPOINT`, `S3_BUCKET`, `S3_REGION`, `S3_ACCESS_KEY`, `S3_SECRET_KEY`. Throws if any env var is missing. |

### dashboard/routes/marketplace.ts (NEW)

Hono route group for marketplace operations. Follows the same pattern as `dashboard/routes/agents.ts`. Uses Hono's built-in `cors()` middleware on all GET routes for cross-origin lander access.

#### Routes

| Route | Method | Body / Params | Returns | Description |
|-------|--------|---------------|---------|-------------|
| `/` | GET | -- | `MarketplaceAgentMeta[]` | List all published agents (CORS enabled) |
| `/:id` | GET | `id` param | `MarketplaceAgentMeta` | Get metadata for a single agent (CORS enabled) |
| `/:id/download` | GET | `id` param | Binary zip (application/zip) | Download agent zip (CORS enabled) |
| `/publish` | POST | JSON: `{ agentId, name, description, author, version, tags }` | `{ success: true, agent: MarketplaceAgentMeta }` | Publish a local agent. Server-side: exports agent, strips MEMORY.md, uploads to S3. |
| `/:id/install` | POST | `id` param, JSON: `{ localId }` | `{ success: true, id: string }` | Download from S3 and import locally. Chains `downloadAgent` into `importAgent(localId, zipBuffer)`. |
| `/:id` | DELETE | `id` param | `{ success: true }` | Remove an agent from the marketplace |

## Important Technical Notes

### SeaweedFS S3 Configuration

The storage backend is a SeaweedFS instance (S3-compatible). The `@aws-sdk/client-s3` must be configured with:
- `endpoint`: `http://s3-fsoscw8wg4og0w0cwwg4kk40.65.109.15.3.sslip.io`
- `forcePathStyle: true` (required for SeaweedFS, which does not support virtual-hosted-style)
- `region`: `us-east-1` (required by the SDK but not meaningful for SeaweedFS)
- Bucket: `agents` (already created)

Env vars use the `S3_` prefix (not `AWS_`) to avoid collisions with any system-level AWS config:
- `S3_ENDPOINT`
- `S3_BUCKET`
- `S3_REGION`
- `S3_ACCESS_KEY`
- `S3_SECRET_KEY`

### Listing via Prefix Scan + Cache (No registry.json)

Instead of maintaining a central `registry.json` that suffers from read-modify-write race conditions on concurrent publishes, `listMarketplaceAgents` scans the bucket for `*.json` files using `ListObjectsV2Command`, fetches each metadata file, and returns the combined array. The result is cached in a module-level variable with a 60-second TTL. Cache is invalidated on publish and delete.

### Server-Side Publish (No Client Zip Round-Trip)

The publish route accepts JSON with `agentId` + metadata fields. It calls `exportAgent(agentId)` from `agent-store.ts` to get the zip buffer, then strips MEMORY.md before uploading to S3. This avoids an unnecessary browser round-trip of downloading and re-uploading the zip.

### MEMORY.md Stripping

The `publishAgent` function in `marketplace.ts` handles stripping. After getting the zip buffer from `exportAgent`, it extracts to a temp directory, overwrites MEMORY.md with an empty string, re-zips, and uploads. This reuses the same `execFileAsync("zip"/"unzip")` pattern already used in `agent-store.ts`.

### Marketplace ID Generation

The marketplace ID is generated as `<author>-<agentId>` (lowercased, spaces replaced with hyphens). This reduces collision risk compared to using just the local agent ID. The upsert behavior means the same author can update their agent by re-publishing with the same author name and agent ID.

### Install Flow (Server-Side Download + Import)

The `/:id/install` route chains `downloadAgent(id)` from `marketplace.ts` with `importAgent(localId, zipBuffer)` from `agent-store.ts`. This avoids the clunky UX of downloading a zip to the browser and re-uploading it. The user just clicks "Install", provides a local ID, and the agent appears in their agents list.

### Lander CORS

The lander is a standalone static HTML file not served by the Hono server. Marketplace GET routes use Hono's `cors()` middleware with `origin: "*"` to allow cross-origin fetches from the lander.

### Lander Graceful Degradation

When the API is unreachable (most common case: lander opened locally without a running server), the Community Agents section is hidden silently. The fetch wraps in a try/catch and only renders the section if agents are successfully loaded.

## Success Criteria

- `POST /api/marketplace/publish` exports agent server-side, strips MEMORY.md, uploads zip + metadata to S3
- `GET /api/marketplace` returns all published agents by scanning S3 prefix (cached 60s)
- `GET /api/marketplace/:id/download` returns the agent zip
- `POST /api/marketplace/:id/install` downloads from S3 and imports locally
- `DELETE /api/marketplace/:id` removes the agent from S3
- Publishing the same author+agent combination again overwrites (upsert)
- "Publish" button on agent detail page opens a form with sensible defaults and publishes to S3
- Dashboard has a "Marketplace" page with search, download, and install
- Lander shows a "Community Agents" section (hidden gracefully when API unavailable)
- Search filters agents by name, description, and tags
- MEMORY.md is stripped when publishing (privacy)
