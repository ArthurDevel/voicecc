# Plan: Migrate Voice Pipeline to Pipecat

## High-Level Goal

Replace our custom Node.js voice pipeline with Pipecat (Python). The Python server uses the Claude Agent SDK for Python (`claude-agent-sdk`) natively -- no cross-language bridge needed.

**Why**: Our custom pipeline is ~2500 lines of Smart Turn ONNX inference, mel spectrogram extraction, parallel audio buffers, TTS pause/resume gates, and false-interruption recovery. Pipecat provides all of this in ~30 lines of configuration. Testing confirms Pipecat works better.

**Architecture split**:
- **Dashboard (TypeScript)**: React + Vite frontend + Hono API backend. Handles auth, agents, settings, device pairing, tunnel. Thin proxy layer -- validates auth then forwards to Python server.
- **Python server**: Pipecat voice pipeline + Claude Agent SDK + text chat + heartbeat + Twilio. Owns all Claude sessions (voice and text). Self-contained.

**Communication**: Both servers run independently. The dashboard knows the Python server's URL via `VOICE_SERVER_URL` env var (default `http://localhost:7861`). The dashboard validates auth on all incoming requests, then proxies to the Python server. The Python server reads its own `.env` for API keys, ports, and agent config. For the tunnel URL (needed by heartbeat for Twilio TwiML), the dashboard calls `POST /config/tunnel-url` on the Python server after the tunnel starts.

## Per-File Methods and Types

### claude_llm_service.py (NEW)

Custom Pipecat `LLMService` subclass wrapping the Python Claude Agent SDK. Uses `ClaudeSDKClient` for persistent multi-turn sessions with full tool use. Does NOT use Pipecat's built-in context accumulation -- the Claude session maintains its own history.

#### Types

```
ClaudeLLMServiceConfig {
  cwd: str                            # working directory for Claude Code session
  system_prompt: str                  # system prompt for voice mode
  allowed_tools: list[str]            # tool allowlist (empty = all)
  initial_prompt: str | None          # optional first message (agent speaks first)
  existing_client: ClaudeSDKClient | None  # pre-existing session (heartbeat handoff)
}
```

#### Methods

| Method | Arguments | Returns | Description |
|--------|-----------|---------|-------------|
| `__init__` | `config: ClaudeLLMServiceConfig` | `None` | Stores config; uses existing_client if provided, otherwise creates SDK client lazily on first message |
| `_ensure_client` | none | `None` | Creates `ClaudeSDKClient` and connects if not already connected |
| `_process_context` | `context: OpenAILLMContext` | `AsyncGenerator[Frame]` | Extracts last user message, sends to SDK client via `client.query()`, yields TextFrames from streaming response. Clears Pipecat context after each turn. |
| `interrupt` | none | `None` | Calls `client.interrupt()` |
| `close` | none | `None` | Calls `client.disconnect()` |

## Important Technical Notes

### Python Claude Agent SDK -- No Bridge Needed

The `claude-agent-sdk` Python package provides the same API as the Node.js version:

```python
async with ClaudeSDKClient(options=options) as client:
    await client.query("Fix the bug")
    async for message in client.receive_response():
        # stream text_delta, tool_start, tool_end, result events
```

Both voice and text chat use this directly. No cross-language bridging.

### Context Accumulation Mismatch

Pipecat's `LLMService._process_context` receives the full message history from context aggregators. But `ClaudeSDKClient` maintains its own conversation history internally. The custom LLM service must:
- Extract only the **last** user message from the context
- Send it via `client.query()`
- Clear the Pipecat context after each turn to prevent unbounded memory growth

### Heartbeat Session Handoff

1. `heartbeat.py` creates a `ClaudeSDKClient` for the check
2. If shouldCall, the live client is stored in `pending_calls` dict keyed by call token
3. Outbound Twilio call placed with TwiML pointing to the voice server's media WebSocket
4. When the call connects, `handle_twilio_websocket` retrieves the live client via `get_pending_client(token)`
5. The `ClaudeLLMService` uses this existing client -- full heartbeat context preserved
6. 60-second cleanup timer closes the client if the call never connects

### Tunnel URL

The tunnel is managed by the dashboard. After the tunnel starts, the dashboard calls `POST /config/tunnel-url` on the Python server so the heartbeat can construct correct TwiML WebSocket URLs for outbound calls.

### Port Architecture

- **Port 8080**: Dashboard Hono server (React SPA, API routes, auth)
- **Port 7860**: Python server -- SmallWebRTC signaling (browser voice calls)
- **Port 7861**: Python server -- FastAPI (text chat, Twilio media, health, heartbeat status)

Both servers run independently. The dashboard proxies to the Python server via `VOICE_SERVER_URL` env var. **Tunnel change**: `startTunnel(voicePort)` -> `startTunnel(dashboardPort)`. All external traffic goes through dashboard auth. The Python server is only reachable from localhost.

### Session Limit

All Claude sessions (voice + text chat) now run in the same Python process. A single `max_concurrent_sessions` counter in `server.py` tracks both voice and chat sessions. This is simpler and more correct than the previous cross-process split.

### Agent-Specific Configuration

Dashboard passes `agentId` as a query param (WebRTC signaling) or in the request body (chat, call registration). The Python server resolves agent config from disk (SOUL.md, MEMORY.md, config.json) and builds the appropriate system prompt.

### Rollback Strategy

Build the Python server in parallel. The old `server/voice/` stays until Phase 4. Git tag `pre-pipecat-migration` before deletion.
