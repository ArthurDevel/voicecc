# Call via Browser Button

## High Level Goal

Remove the "New Browser Session" button from the Sidebar and add a "Call via Browser" button next to "Call Me" on the AgentDetail page. This button opens the same QR code + pairing modal, but threads the agent's ID through the entire browser call flow so the voice session uses the agent's personality, system prompt, and voice preference. Show a tooltip when browser calling is not enabled.

Currently, browser calls are fully agent-agnostic (hardcoded DEFAULT_CONFIG). The Twilio outbound call path already loads agent config. We mirror that pattern for browser calls.

## Important Technical Notes

### AgentId flow through the system

The agentId travels via the URL, not through the pairing/token system. The pairing system remains agent-agnostic (handles auth only).

```
AgentDetail                          Call.tsx                        browser-server.ts
    |                                    |                                |
    | QR = tunnelUrl/call?code=X         |                                |
    |         &agentId=Y                 |                                |
    |                                    |                                |
    |                      User scans QR |                                |
    |                      Extracts agentId from URL                      |
    |                      Stores agentId in localStorage                 |
    |                      Pairs device (agentId not involved)            |
    |                                    |                                |
    |                      WS /audio?token=T&agentId=Y                   |
    |                                    |-----> validates agentId        |
    |                                    |       loads agent config       |
    |                                    |       creates VoiceSession     |
```

Returning devices (cached token, no `?agentId` in URL) read `agentId` from localStorage.

### Agent config loading in browser-server.ts

Mirror the pattern from `twilio-server.ts:448-490`:
1. Extract `agentId` in upgrade handler, pass to session creation (validation happens async in `createSession`)
2. Call `getAgent(agentId)` to load SOUL.md and config
3. Build `customSystemPrompt` from `DEFAULT_SYSTEM_PROMPT` (loaded from `system.md`) + agent's `soulMd`
4. Use `customSystemPrompt` field (NOT `systemPrompt`) -- `systemPrompt` gets wrapped in a preset, `customSystemPrompt` replaces it entirely
5. Set `cwd` to `join(AGENTS_DIR, agentId)`
6. Override TTS voice if `agent.config.voice?.elevenlabs` exists
7. On agent load failure: log error and close WebSocket (do not fall back silently)

### systemPrompt vs customSystemPrompt

`browser-server.ts` currently uses `claudeSession.systemPrompt` (line 69). When adding agent support, agent calls must use `claudeSession.customSystemPrompt` instead. The `systemPrompt` field gets wrapped in a `claude_code` preset, while `customSystemPrompt` completely replaces the system prompt. This matches how `twilio-server.ts` handles agent calls.
