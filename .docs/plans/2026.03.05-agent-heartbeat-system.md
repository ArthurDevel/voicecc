# Agent System with Heartbeat

## Goal

Add an OpenClaw-inspired agent system to VoiceCC. Users can create named agents, each with its own personality (SOUL.md), persistent memory (MEMORY.md), heartbeat checklist (HEARTBEAT.md), and configuration. Agents run periodic heartbeat checks using a full Claude Code session with tool access — so they can check email, calendar, APIs, etc. When a heartbeat determines the user should be contacted, the agent initiates an outbound Twilio call. The dashboard provides read-only views of each agent's files and a "Call Me" button for on-demand outbound calls. Default inbound voice behavior is untouched.

## Types and Methods Per File

### services/agent-store.ts (NEW)

File-based storage for agents at `~/.claude-voice-agents/<agentId>/`. Each agent directory contains `SOUL.md`, `MEMORY.md`, `HEARTBEAT.md`, and `config.json`. The agent itself reads/writes its own files during voice sessions via Claude Code SDK filesystem access. This module is used by the heartbeat scheduler and the dashboard API (read-only).

#### Types

```
AgentConfig {
  heartbeatIntervalMinutes: number    // default: 10
  phoneNumber: string                 // E.164 format, e.g. "+15551234567"
  enabled: boolean
}

Agent {
  id: string
  soulMd: string
  memoryMd: string
  heartbeatMd: string
  config: AgentConfig
}

AgentSummary {
  id: string
  enabled: boolean
  phoneNumber: string
  heartbeatIntervalMinutes: number
}
```

#### Methods

| Method | Arguments | Returns | Description |
|--------|-----------|---------|-------------|
| `listAgents` | none | `Promise<AgentSummary[]>` | Reads all agent directories, parses only config.json for each. Returns empty array if AGENTS_DIR does not exist. |
| `getAgent` | `id: string` | `Promise<Agent>` | Reads all four files (SOUL.md, MEMORY.md, HEARTBEAT.md, config.json) from the agent's directory. Throws if agent does not exist. |
| `createAgent` | `id: string, soulMd: string, heartbeatMd: string, config: AgentConfig` | `Promise<void>` | Creates agent directory + writes SOUL.md, empty MEMORY.md, HEARTBEAT.md, config.json. Throws if agent already exists. |
| `deleteAgent` | `id: string` | `Promise<void>` | Recursively removes agent directory. Throws if agent does not exist. |

### services/heartbeat.ts (NEW)

Interval-based scheduler that checks all enabled agents periodically. Spawns a full Claude Code session (with tool access) per heartbeat check, so the agent can execute whatever HEARTBEAT.md instructs (check email, calendar, files, APIs, etc.).

#### Types

```
HeartbeatResult {
  agentId: string
  shouldCall: boolean
  reason: string
  timestamp: number
}
```

#### Methods

| Method | Arguments | Returns | Description |
|--------|-----------|---------|-------------|
| `startHeartbeat` | none | `void` | Starts a 60-second `setInterval` that calls `checkAllAgents`. Ensures AGENTS_DIR exists. |
| `stopHeartbeat` | none | `void` | Clears the interval timer. |
| `getHeartbeatStatus` | none | `Record<string, HeartbeatResult>` | Returns the last heartbeat result per agent (plain object, JSON-serializable). Used by the API. |
| `checkAllAgents` | none | `Promise<void>` | Lists enabled agents, skips those whose interval hasn't elapsed, calls `checkSingleAgent` for due agents. |
| `checkSingleAgent` | `agent: Agent` | `Promise<HeartbeatResult>` | Spawns Claude Code session via SDK `query()` with agent's SOUL.md + MEMORY.md + HEARTBEAT.md as system prompt, full tool access. Parses JSON response `{shouldCall, reason}`. |
| `initiateAgentCall` | `agent: Agent` | `Promise<void>` | Uses Twilio SDK `client.calls.create()` to place outbound call. TwiML connects a `<Stream>` to the Twilio WebSocket server with `?agentId=<id>` in the URL. |

## Important Technical Notes

### Heartbeat Spawns Full Claude Code Sessions

The heartbeat does NOT use a simple text-only prompt. It spawns a full Claude Code session via the SDK `query()` with `permissionMode: "bypassPermissions"`, giving the agent access to all tools (bash, file read/write, web fetch, etc.). This is critical because HEARTBEAT.md may instruct the agent to check email, calendar, run scripts, etc. The session's `appendSystemPrompt` combines SOUL.md + MEMORY.md + HEARTBEAT.md. The user-facing prompt is: "Execute the heartbeat checklist in HEARTBEAT.md. Use tools as needed to check all conditions. Respond with exactly one JSON object: `{\"shouldCall\": true/false, \"reason\": \"brief explanation\"}`".

### Heartbeat Response Parsing

The Claude Code session may produce tool calls and text output before the final JSON response. To extract the result, scan the streamed messages for the last `assistant` text block, then parse JSON from it. If parsing fails or the session errors, log the failure and treat it as `shouldCall: false` (fail safe — don't call the user on error).

### Outbound Call Flow via Twilio (Cross-Process Token Registration)

The Twilio server runs as a **separate child process** (spawned via `services/twilio-manager.ts`). The `activeCalls` map is module-scoped inside that process. For outbound calls to work, the token must be registered in the twilio-server process before Twilio connects the WebSocket.

**Solution:** Add a `POST /register-call` HTTP endpoint to `sidecar/twilio-server.ts` that accepts `{ token, agentId }` and registers it in `activeCalls`. The heartbeat/API route calls this endpoint on localhost before placing the Twilio call.

Full outbound call flow:
1. Check preconditions: tunnel is running (`getTunnelUrl()` from `services/tunnel.ts`) AND Twilio server is running (`getStatus()` from `services/twilio-manager.ts`)
2. Generate a UUID token
3. Call `POST http://localhost:{twilioPort}/register-call` with `{ token, agentId }` → registers in `activeCalls`
4. Read env for `TWILIO_ACCOUNT_SID`, `TWILIO_AUTH_TOKEN`
5. Get first Twilio phone number via `client.incomingPhoneNumbers.list({ limit: 1 })`
6. Call `client.calls.create({ to, from, twiml })` where TwiML is `<Response><Connect><Stream url="wss://{tunnelUrl}/media/{token}?agentId={agentId}" /></Connect></Response>`
7. Twilio connects WebSocket → `handleWebSocketUpgrade` finds token in `activeCalls` (with agentId) → `handleStreamStart` loads agent → voice session with agent's system prompt

### Concurrent Heartbeat Guards

Multiple heartbeat checks could theoretically overlap if a Claude session takes longer than 60 seconds. Track in-flight checks per agent using a `Set<string>` of currently-running agent IDs. Skip agents that are already being checked. This prevents duplicate calls and runaway resource usage.

### Heartbeat Session Timeout

Each `checkSingleAgent` call must have a timeout (120 seconds). If the Claude session does not complete in time, abort via `q.interrupt()` and log the failure. Treat timeout as `shouldCall: false`. Without this, a stuck session blocks that agent's heartbeat permanently.

### Heartbeat query() Pattern

The heartbeat imports `query` directly from `@anthropic-ai/claude-code` (same import as `claude-session.ts` line 17), NOT via the `claude-session.ts` wrapper. It uses the single-prompt string form:

```
const q = query({ prompt: "Execute the heartbeat...", options: {
  pathToClaudeCodeExecutable: CLAUDE_BIN,
  appendSystemPrompt: soulMd + "\n\n" + memoryMd + "\n\n" + heartbeatMd,
  permissionMode: "bypassPermissions",
} });
for await (const event of q) { /* collect assistant text */ }
```

Timeout: wrap with `AbortController` + `setTimeout(120_000)` and pass the signal in options. On timeout, the query is aborted and treated as `shouldCall: false`.

### Tunnel Precondition for Outbound Calls

`initiateAgentCall` must validate that the tunnel is running (via `getTunnelUrl()` from `services/tunnel.ts`) before placing a call. The `/:id/call` API route must also check this and return a 400 error if the tunnel is down. Without a tunnel URL, the TwiML `<Stream>` URL would be invalid and the call would hang.

### Agent ID Validation

Agent IDs must be filesystem-safe. Validate on creation: alphanumeric + hyphens only, 1-50 chars. Reject IDs containing path separators, dots, or special characters.

### Interval Drift

The 60-second global `setInterval` means an agent with `heartbeatIntervalMinutes: 10` will actually be checked at 10 minutes + up to 59 seconds of drift. This is acceptable for the use case.

## Success Criteria

- Creating an agent via `POST /api/agents` writes four files to `~/.claude-voice-agents/<agentId>/`
- `GET /api/agents` returns all agents with summary info
- `GET /api/agents/:id` returns full agent data including all markdown files
- Heartbeat scheduler logs periodic checks to console at the configured interval
- Heartbeat with tool access can actually execute checks (e.g. read files, run commands)
- "Call Me" button initiates an outbound Twilio call with the agent's personality
- Agent detail page displays read-only SOUL.md, MEMORY.md, HEARTBEAT.md, and config.json
- Default inbound voice behavior is completely unaffected
- Deleting an agent removes its directory
